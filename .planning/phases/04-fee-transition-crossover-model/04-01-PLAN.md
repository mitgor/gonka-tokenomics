3. **Call location:** Call `_add_tail_emission_toggle()` AFTER the PARAM_GROUPS loop but BEFORE `_add_scenario_selector()` in `build_assumptions_tab()`. The function does NOT need a `current_row` parameter since it modifies an existing cell. Signature: `_add_tail_emission_toggle(ws, param_refs)`.

Implementation:

```python
def _add_tail_emission_toggle(ws, param_refs):
    """Add ON/OFF DataValidation to the Tail Emission Toggle parameter cell.

    The cell already exists from the PARAM_GROUPS loop. This function
    adds a dropdown constraint so the user can only enter ON or OFF.

    Args:
        ws: The Assumptions worksheet.
        param_refs: Dict containing "Tail Emission Toggle" -> "Assumptions!$B$NN".
    """
    # Parse row number from param_refs (format: "Assumptions!$B$NN")
    ref = param_refs["Tail Emission Toggle"]
    row = int(ref.split("$")[-1])

    toggle_cell = ws.cell(row=row, column=2)

    dv = DataValidation(
        type="list",
        formula1='"ON,OFF"',
        allow_blank=False,
    )
    dv.prompt = "Select ON or OFF"
    dv.promptTitle = "Tail Emission"
    ws.add_data_validation(dv)
    dv.add(toggle_cell)
```

In `build_assumptions_tab()`, add the call at line ~218 (after the PARAM_GROUPS loop, before scenario selector):

```python

    _add_tail_emission_toggle(ws, param_refs)

    # --- Scenario Selector (dropdown + MATCH + CHOOSE) ---
    current_row = _add_scenario_selector(ws, current_row, param_refs)
```

**Rows 3-34 (32 data rows):** For each row `i` (0-based), `row = 3 + i`, `es_row = emission_meta["data_start_row"] + i`:

Determine `days` per period:
- i=0..23 (monthly): days=30
- i=24..31 (annual): days=365

**Column A (Period Label):** Cross-ref from Emission Schedule.
```
={es_sheet}!{es_period_col}{es_row}
```
Style: `crossref_cell`

**Column B (Developer Count):** Compound growth from base developers. Use `start_epoch / 365` for fractional years.
```
={base_devs_ref}*(1+{mod_growth_ref})^({es_sheet}!{es_start_col}{es_row}/365)
```
Style: `integer`
NOTE: Uses moderate growth as the base developer count projection. The 3 growth scenarios in fee revenue columns C/D/E each use their own growth rate.

**Column C (Fee Revenue - Low Growth):**
```
={base_devs_ref}*(1+{low_growth_ref})^({es_sheet}!{es_start_col}{es_row}/365)*{rev_per_dev_ref}*{days}/365
```
Style: `currency`

**Column D (Fee Revenue - Base Growth):**
```
={base_devs_ref}*(1+{mod_growth_ref})^({es_sheet}!{es_start_col}{es_row}/365)*{rev_per_dev_ref}*{days}/365
```
Style: `currency`

**Column E (Fee Revenue - High Growth):**
```
={base_devs_ref}*(1+{high_growth_ref})^({es_sheet}!{es_start_col}{es_row}/365)*{rev_per_dev_ref}*{days}/365
```
Style: `currency`

**Column F (Emission Value $):** Raw emission value = mining_emission_GNK * active_price.
```
={es_sheet}!{es_mining_col}{es_row}*{tp_sheet}!{tp_active_col}{es_row}
```
Style: `currency`

**Column G (Effective Emission Value $):** Applies tail emission toggle. If toggle is "ON", uses MAX(mining_GNK, tail_rate * days) * price. If "OFF", uses raw emission value (same as F).
```
=IF({tail_toggle_ref}="ON",MAX({es_sheet}!{es_mining_col}{es_row},{tail_rate_ref}*{days})*{tp_sheet}!{tp_active_col}{es_row},F{row})
```
Style: `currency`

**Column H (Crossover Ratio - Low):**
```
=IFERROR(C{row}/G{row},0)
```
Style: `number` (will show as 0.0, 1.2, etc.)

**Column I (Crossover Ratio - Base):**
```
=IFERROR(D{row}/G{row},0)
```
Style: `number`

**Column J (Crossover Ratio - High):**
```
=IFERROR(E{row}/G{row},0)
```
Style: `number`

**Column K (Host Share):** 70% of base fee revenue (col D), period-adjusted.
```
=D{row}*{host_share_ref}
```
Style: `currency`

**Column L (AI Fund Share):** 20% of base fee revenue.
```
=D{row}*{ai_fund_ref}
```
Style: `currency`

**Column M (Buyback Share):** 5% of base fee revenue.
```
=D{row}*{buyback_ref}
```
Style: `currency`

**Column N (Yield Pool Share):** 5% of base fee revenue.
```
=D{row}*{yield_ref}
```
Style: `currency`

**Design decision:** The 9-cell RATIO matrix at Year 10 (rows 38-40) already provides the full 3x3 growth-rate x price-scenario breakdown. The YEAR matrix uses a simpler approach: reference the data table's existing crossover ratio columns H/I/J, which respond to the Active Price scenario selector. This avoids fragile array formulas while still delivering the crossover timing insight. Users change the scenario selector to see different price contexts.

**Implementation:**

Row 44: A44="Low Growth", B44 formula (merged B44:D44):
```
=IFERROR(INDEX($A$3:$A$34, MATCH(1, $H$3:$H$34, 1)), "Never")
```
Row 45: A45="Base Growth", B45 formula (merged B45:D45):
```
=IFERROR(INDEX($A$3:$A$34, MATCH(1, $I$3:$I$34, 1)), "Never")
```

Row 46: A46="High Growth", B46 formula (merged B46:D46):
```
=IFERROR(INDEX($A$3:$A$34, MATCH(1, $J$3:$J$34, 1)), "Never")
```

MATCH with match_type=1 finds the first value >= 1 in the ratio column. IFERROR wraps it to show "Never" if crossover doesn't happen within 10 years.

Merge B:D for each row since all use Active Price (single result per growth rate).

## Anti-Patterns to Avoid

- **Do NOT hardcode parameter values** -- every value must come from param_refs or cross-sheet references
- **Do NOT use named ranges** -- use direct cell references (project convention from FEATURES.md)
- **Do NOT forget the days factor** -- multiply fee revenue by days/365 for each period (30/365 for monthly, 365/365 for annual)
- **Do NOT use CSE array formulas** -- the INDEX/MATCH(TRUE,INDEX(...)) pattern works without Ctrl+Shift+Enter
- **Do NOT create a stacked bar without overlap=100** -- that's Plan 02's job, but note for awareness
- **Do NOT apply conditional formatting** -- that's Plan 02's scope (charts + formatting)
- **Do NOT forget IFERROR wrappers** on division formulas (division by zero when emission value is 0)
- **Do NOT mix up price columns** -- Token Price B=Conservative, C=Moderate, D=Aggressive (NOT Active Price F)
- **Do NOT forget quote_sheetname()** -- "Emission Schedule" has a space, must be quoted in cross-sheet refs
