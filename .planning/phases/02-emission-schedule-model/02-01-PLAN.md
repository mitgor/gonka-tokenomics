**Sheet setup:**
- Create worksheet named "Emission Schedule"
- Set tab color to TAB_COLOR_CALC (gray, from styles.py)
- Row 1: merged title "EMISSION SCHEDULE MODEL" with section_header style
- Row 2: column headers with header style

**Column layout (9 data columns):**
- A: Period Label (text, e.g., "Y1 M01", "Year 3")
- B: Start Epoch (integer)
- C: End Epoch (integer)
- D: Mining Emission (GNK) -- closed-form formula
- E: Community Pool Unlock (GNK) -- linear formula
- F: Founder Vesting (GNK) -- conditional formula
- G: Total New Supply (GNK) -- sum of D+E+F
- H: Cumulative Circulating (GNK) -- running sum
- I: Annualized Inflation Rate (%) -- computed per period

**Period definitions (32 rows, data-driven):**
Build a PERIODS list in Python:
- Monthly Year 1-2: 24 periods, each 30 days. Labels "Y1 M01" through "Y2 M12". Epochs: 0-29, 30-59, ..., 690-719.
- Annual Year 3-10: 8 periods, each 365 days. Labels "Year 3" through "Year 10". Epochs: 720-1084, 1085-1449, ..., 3285-3649.

**Data rows (rows 3-34):** For each of the 32 periods:

Column A: Write period label (text).
Column B: Write start epoch (integer value). Apply "integer" style.
Column C: Write end epoch (integer value). Apply "integer" style.

Column D (Mining Emission): Closed-form geometric series partial sum formula:
```
={e0_ref}*EXP(-{r_ref}*B{row})*(1-EXP(-{r_ref}*{days}))/(1-EXP(-{r_ref}))
```
Where `e0_ref = param_refs["Initial Daily Emission"]`, `r_ref = param_refs["Decay Rate"]`, `days` is 30 for monthly or 365 for annual. Apply "tokens" style.

Column E (Community Pool Unlock): Linear unlock formula:
```
={cp_ref}/{cp_period_ref}*{days}
```
Where `cp_ref = param_refs["Community Pool"]` (120M), and use a hardcoded 3650 for the 10-year unlock period (consistent with the model horizon). The formula becomes `={cp_ref}/3650*{days}` where days is 30 or 365. Apply "tokens" style.

IMPORTANT: The research recommends a configurable CP Unlock Period parameter. Check if "Community Pool Unlock Period" exists in param_refs. If not, use the literal 3650 (10 years in days). This is acceptable because the Community Pool unlock schedule is approximate and will be refined in Phase 6 (Treasury).

Column F (Founder Vesting): Linear vesting over 48 months with cutoff. The founder allocation vests linearly over the vesting period:
```
=IF(B{row}<{vest_months_ref}*30, {founder_ref}/{vest_months_ref}*{days}/30, IF(C{row}<={vest_months_ref}*30, {founder_ref}/{vest_months_ref}*(({vest_months_ref}*30-B{row})/30), 0))
```
Simplification: Since monthly periods are 30 days and vesting is 48 months (1440 days), for monthly periods (rows 3-26) the formula is simply `={founder_ref}/{vest_months_ref}` (one month's worth). For annual periods, check if the entire period is within vesting (epochs < 1440): if yes, full year vesting `={founder_ref}/{vest_months_ref}*12`; if the period straddles the vesting end (Year 4 starts epoch 1085, ends 1449 -- straddles 1440), compute partial; if beyond vesting (epoch >= 1440), output 0.

Use `founder_ref = param_refs["Founder Allocation"]`, `vest_months_ref = param_refs["Founder Vesting Period"]` (value is 48).

PRACTICAL APPROACH for founder vesting formulas:
- Monthly rows (Y1-Y2, rows 3-26): All within 48-month vesting. Formula: `={founder_ref}/{vest_months_ref}`
- Year 3 row (row 27, epochs 720-1084): All within vesting. Formula: `={founder_ref}/{vest_months_ref}*12`
- Year 4 row (row 28, epochs 1085-1449): Straddles vesting end at epoch 1440 (48*30). Formula for partial: `={founder_ref}/{vest_months_ref}*((48*30-B{row})/30)` but reference vesting period from param_refs. Use: `={founder_ref}/{vest_months_ref}*(({vest_months_ref}*30-B{row})/30)`
- Year 5-10 rows (rows 29-34): Beyond vesting. Value: 0

To make this fully formula-driven (so changing Founder Vesting Period on Assumptions recalculates):
Use an IF-based formula for ALL rows:
```
=IF(C{row}<={vest_ref}*30, {founder_ref}/{vest_ref}*{days}/30, IF(B{row}>={vest_ref}*30, 0, {founder_ref}/{vest_ref}*(({vest_ref}*30-B{row})/30)))
```
Where `vest_ref = param_refs["Founder Vesting Period"]`, `days` is period length (30 or 365).
Apply "tokens" style.

Column G (Total New Supply): `=D{row}+E{row}+F{row}`. Apply "tokens" style.

Column H (Cumulative Circulating):
- Row 3 (first period): `=G3`
- Rows 4-34: `=H{row-1}+G{row}`
Apply "tokens" style.

Column I (Annualized Inflation Rate): `=(G{row}/(C{row}-B{row})*365)/H{row-1}`
- Row 3 (first period): Use total supply start context. Since nothing is circulating before period 1, inflation is undefined. Write a note or use `=G3/(C3-B3)*365/G3` (first-period inflation relative to first-period supply itself = annualized rate). OR simply: for row 3, the denominator is 0 (no prior circulating), so use `=""` or a text label "N/A". Better: write 0 and note in the header.
- Rows 4-34: `=(G{row}/(C{row}-B{row})*365)/H{row-1}`
Apply "percent" style. Format shows as percentage (e.g., 15.3%).

**Validation rows (rows 36-38):**
Row 36: "Validation: Closed-Form Total" | Formula: `={e0_ref}*(1-EXP(-{r_ref}*3650))/(1-EXP(-{r_ref}))`
Row 37: "Validation: Sum of Periods" | Formula: `=SUM(D3:D34)`
Row 38: "Validation: Difference" | Formula: `=ABS(B36-B37)` | Apply warning_cell style if difference > 1: use conditional approach or just always apply "tokens" style and let the user see the value.

Apply "tokens" style to validation formula cells. Apply "formula_cell" style to validation label cells.
