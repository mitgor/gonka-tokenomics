**Document structure:**

1. **Executive Summary** (200-300 words): The inference provider landscape has four segments. Gonka occupies a unique position as the only decentralized provider with agent-native API extensions. Key finding: Gonka's biggest barriers are ecosystem integration (not built into OpenClaw) and missing table-stakes infrastructure (docs, signup, pricing page), not feature gaps.

2. **Landscape Segmentation Framework** (200-300 words): Explain the 2x2 categorization model:
   - X-axis: Centralized vs Decentralized infrastructure
   - Y-axis: Single-provider vs Multi-provider router
   - Third dimension overlay: Agent-awareness (none / partial / native)
   
   Include a text-based 2x2 grid diagram:
   ```
                    Single Provider          Multi-Provider Router
   Centralized    | OpenAI, Anthropic,      | OpenRouter, LiteLLM,
                  | Google, DeepSeek,       | Portkey
                  | Mistral                 |
   ---------------+-------------------------+------------------------
   Decentralized  | GONKA, Akash (AkashML), | (empty — opportunity?)
                  | SaladCloud              |
                  | io.net, Render          |
   ```

3. **Segment 1: Centralized API Providers** (500-700 words): Cover OpenAI, Anthropic, Google, DeepSeek, Mistral. For each: key strength, OpenClaw integration status (built-in or not), agent-relevant features, threat level to Gonka (LOW/MEDIUM/HIGH). Note that all 5 are built-in OpenClaw providers.

4. **Segment 2: Multi-Provider Routers** (500-700 words): Cover OpenRouter (PRIMARY competitor — deepest analysis), LiteLLM, Portkey. OpenRouter is built-in to OpenClaw. Explain why OpenRouter is the real competitive threat: same target user (OpenClaw devs who want model flexibility), zero-config integration, 500+ models. LiteLLM is self-hosted open-source alternative.

5. **Segment 3: Dedicated Inference** (400-500 words): Cover Together AI, Groq, DeepInfra, Fireworks AI, SiliconFlow. Note the Blackwell GPU impact: these providers are getting 10x cheaper per token (cite NVIDIA GTC 2026). Together AI is closest on pricing. Groq sets latency benchmarks (0.13s TTFT, Groq 3 LPU from Nvidia acquisition Dec 2025).

6. **Segment 4: Decentralized GPU Networks** (500-700 words): Cover Gonka, Akash (AkashML), io.net, Render, SaladCloud. Highlight Gonka's unique position: only decentralized provider with agent-native extensions (sessions, memory, tiering, webhooks). AkashML is closest competitor (OpenAI-compatible API since Nov 2025, 65 datacenters) but lacks agent extensions. Note SaladCloud has OpenClaw-specific guides.

7. **Competitive Positioning Summary** (300-400 words): Where Gonka wins, where it loses, and what determines the outcome. Key insight: Gonka doesn't compete on model breadth or ecosystem size — it competes on agent-native infrastructure + decentralized cost structure. The question is whether those advantages outweigh the integration friction.

8. **Gap Analysis: Must Close Before GTM Push** (500-700 words): Use this exact table structure with these specific gaps:
   | Gap | Why Critical | v1.2 Tech Debt? | Competitive Impact | Priority |
   - Not a built-in OpenClaw provider (manual JSON config required; OpenRouter is zero-config) — NOT tech debt — CRITICAL
   - No public documentation site (developers cannot evaluate without docs) — NOT tech debt — CRITICAL
   - No self-serve API key signup (manual key provisioning blocks adoption) — NOT tech debt — CRITICAL
   - No public pricing page (cannot compare vs competitors; "cut your bill 70%" unverifiable) — NOT tech debt — CRITICAL
   - In-memory sessions (sessions lost on restart; undermines session persistence differentiator) — YES v1.2 tech debt — HIGH
   
   For each gap: explain why it blocks GTM, what the competitive standard is, and what "closed" looks like.

9. **Gap Analysis: Can Defer** (400-500 words): Same table structure with these gaps:
   - Single model (K2.5 only, 3 quants) — position as "best agent model" first — defer until Active/Heavy user tier
   - JSON key storage — security concern at scale, OK for early adopters — YES v1.2
   - TF-IDF search (not vector embeddings) — memory works but lower recall — YES v1.2
   - No GPU load balancing — single-node OK for early traffic — YES v1.2
   - No developer dashboard — admin API exists, CLI-first is fine — defer until Active tier
   - No SLA guarantee — publish uptime stats instead — defer until enterprise outreach
   
   For each: explain why it can wait and when it should be addressed.

10. **Recommendations for Phase 16-20** (200-300 words): How this landscape analysis should inform downstream phases. Specifically:
    - Phase 16 (personas): Primary competitor for persona pain points is OpenRouter, not OpenAI
    - Phase 17 (messaging): Lead with agent-native features, not decentralization or cost
    - Phase 19 (partnerships): Getting built into OpenClaw is the single highest-impact GTM action
    - Phase 20 (PLG): Must-close gaps define the minimum viable GTM checklist

**Anti-patterns to avoid:**
- Do NOT spend equal analysis depth on all providers — OpenRouter gets deepest treatment, io.net/Render get lightest
- Do NOT present gaps without priority tiers — every gap must be "must close" or "can defer"
- Do NOT overstate Gonka's cost advantage — use "potential" and "contingent on pricing" language
- Cross-reference the feature matrix document where relevant: "As shown in the feature matrix (gonka_competitive_feature_matrix.md), Gonka wins on sessions and tiering..."
