  <action>
Append AAARRRP journey maps to the existing `output/gonka_developer_personas.md` file, after the persona cards section.

**Section structure:**
1. Journey Maps header with brief AAARRRP framework explanation (cite Phil Leggetter 2016)
2. One complete journey map table per persona (3-4 tables total)
3. Cross-persona insights section identifying common patterns and divergences across personas

**Per-persona journey map table format:**
| Stage | Touchpoint | Action | Objection | Content/Asset Needed | Key Metric |

**7 stages per persona** (all mandatory):
1. **Awareness** -- How this persona first hears about Gonka. Must reference specific channels (Reddit, Discord, GitHub, ClawHub) not generic "social media"
2. **Acquisition** -- How they sign up / get API key. Reference the actual signup flow
3. **Activation** -- First successful inference call. Reference openclaw.json config change, specific "aha moment" for this persona's use case
4. **Retention** -- What keeps them using Gonka beyond day 1. Different per persona based on their primary driver
5. **Revenue** -- Conversion to paid usage. Reference pricing tiers relevant to their workload tier
6. **Referral** -- How they recommend Gonka. Must be persona-specific (solo dev tweets vs startup CTO writes blog post)
7. **Product** -- How their feedback shapes Gonka. Reference specific feedback channels

**Per-stage requirements:**
- Touchpoint: Must be a specific place/medium (not "online" or "social media")
- Action: Concrete developer action (not "learns about Gonka")
- Objection: Specific blocker sourced from ARCHITECTURE.md objection map or PITFALLS.md. Each persona should have different objections at each stage reflecting their unique decision drivers
- Content/Asset Needed: What Gonka must create/provide. Be specific (e.g., "comparison blog post: Gonka vs OpenRouter for heartbeat-heavy agents" not "marketing content")
- Key Metric: Measurable KPI for this stage (e.g., "unique visitors to docs.gonka.ai from Reddit" not "awareness")

**Cross-persona insights section must include:**
- Common objections across all personas (universal blockers)
- Stage where each persona is most likely to drop off (and why)
- Content assets that serve multiple personas simultaneously
- Priority ranking of stages by impact (where Gonka should invest first)

**Critical anti-patterns to avoid:**
- Do NOT create generic SaaS funnels that could apply to any API product (PITFALLS.md Pitfall 3)
- Do NOT use identical touchpoints/objections across all personas -- the whole point is differentiation
- Do NOT reference "blockchain" or "decentralization" as touchpoints in Awareness stage -- Web2 developers discover via performance/cost comparisons, not crypto channels
- Touchpoints must reference OpenClaw-specific artifacts: ClawHub, openclaw.json, heartbeat system, agent sessions
