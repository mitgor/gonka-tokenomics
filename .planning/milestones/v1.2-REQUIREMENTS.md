## Model Serving

- [x] **SERV-01**: Kimi K2.5 can be deployed via vLLM with tensor parallelism across multiple GPUs — `serving/serve.py`
- [x] **SERV-02**: vLLM serves OpenAI-compatible `/v1/chat/completions` endpoint for K2.5 — `serving/serve.py`, `gateway/main.py`
- [x] **SERV-03**: K2.5 tool calling works via vLLM's `kimi_k2` parser — `serving/serve.py` (--tool-call-parser flag)
- [x] **SERV-04**: K2.5 reasoning/thinking mode works via vLLM's `kimi_k2` reasoning parser — `serving/serve.py` (--reasoning-parser flag)
- [x] **SERV-05**: Docker container configuration packages vLLM + K2.5 for GPU node deployment — `serving/Dockerfile`, `serving/docker-compose.yml`
- [x] **SERV-06**: Multi-model routing allows serving K2.5 alongside other models from a single gateway — `gateway/router.py`, `config/models.yaml`
- [x] **SERV-07**: Quantized K2.5 variants (Q4, Q2) can be deployed for cost-optimized tiers — `serving/docker-compose.yml` (3 profiles), `config/models.yaml`
- [x] **SERV-08**: Health check endpoint reports model status, GPU utilization, and queue depth — `serving/health.py`

## API Gateway

- [x] **GATE-01**: FastAPI gateway proxies requests to vLLM backends with OpenAI-compatible interface — `gateway/main.py`
- [x] **GATE-02**: API key authentication validates requests before forwarding to model backends — `gateway/auth.py`
- [x] **GATE-03**: Rate limiting enforces per-key request limits (configurable per tier) — `gateway/rate_limit.py`
- [x] **GATE-04**: Usage metering tracks tokens consumed per API key per model per time period — `gateway/metering.py`
- [x] **GATE-05**: Gateway routes requests to correct model backend based on model parameter — `gateway/router.py`
- [x] **GATE-06**: Gateway returns standardized error responses matching OpenAI error format — `gateway/errors.py`
- [x] **GATE-07**: Gateway supports streaming responses (SSE) for chat completions — `gateway/main.py` (StreamingResponse)
- [x] **GATE-08**: Admin API exposes usage statistics, key management, and model status — `admin/api.py`

## Agent Inference Extensions

- [x] **AGNT-01**: Session persistence stores conversation history server-side keyed by session ID — `agent/sessions.py`
- [x] **AGNT-02**: Memory API allows agents to store and retrieve long-term context with semantic search — `agent/memory.py`
- [x] **AGNT-03**: Model tiering auto-routes requests based on configurable rules — `agent/tiering.py`
- [x] **AGNT-04**: Webhook callbacks notify agents asynchronously when inference completes — `agent/webhooks.py`
- [x] **AGNT-05**: Usage dashboard shows per-session token consumption and model usage breakdown — `admin/api.py`
- [x] **AGNT-06**: Session TTL and cleanup automatically expire inactive sessions — `agent/sessions.py`
